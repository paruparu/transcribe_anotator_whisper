# transcribe_annotator_whisper

音声インタビューを **文字起こし → 話者ラベル付け・誤字修正 → テキスト書き出し** するためのローカルツール一式です。

6つのスクリプトから成ります。文字起こしは環境で選びます（**Mac なら `transcribe_mlx.py`**、
GPU 機なら `transcribe.py` か `diarize_d1.py`）。外で作ったものは `import_whisper.py` で取り込みます。

| スクリプト | 役割 |
| --- | --- |
| `transcribe.py` | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) を使い、ディレクトリ内の音声を一括で文字起こし |
| `transcribe_mlx.py` | **Apple Silicon の GPU で文字起こし（Mac ならこちら）** |
| `diarize_local.py` | 文字起こし済みの音声に、話者分離だけをローカルで足す |
| `diarize_d1.py` | 文字起こしの本文を変えずに話者分離を足す（推奨パイプライン） |
| `import_whisper.py` | 外で作った文字起こし（JSON/SRT）を `recordings/` に取り込む |
| `annotator.py` | 文字起こしと音声をブラウザ上で並べ、発話者ロールのラベル付け・誤字修正・書き出しを行うGUI |

最終出力は MAXQDA などに読み込める、行頭にロールを括弧書きしたシンプルなテキストです。

```
(インタビュアー) はい、ということでですね
(インタビュイー) よろしくお願いします
```

---

## いちばん短い使い方

**Mac なら、ターミナルで打つのは1行だけです。**あとは全部ブラウザでできます。

```bash
python annotator.py --source-dir ~/Documents/録音   # よく音声を置く場所を渡しておく
# → http://127.0.0.1:8000/ が開く
```

1. **「文字起こし」を押す** — 取り込み元から音声を選んで「追加する」
2. **話者の人数を入れて「実行」** — 文字起こしと話者分離が順に走る（30分で約10分）
   処理中もアノテーションを続けられます。終わると「話者を割り当てますか」と聞かれます
3. **「割り当てる」→ 名前を付ける** — `SPEAKER_00` が誰なのかは人が決めます。
   右の発話行数が手がかりです（質問する人がいちばん多いことが多い）
4. **聞きながら直す** — `Space` で再生、`1`〜`9` で話者、`Enter` で本文を編集
5. **「書き出し」** — `recordings/<名前>_annotated.txt` ができます

初回だけモデル（約2.9GB）が自動で落ちてくるので、1本目は余計に時間がかかります。

事前に必要なのは[セットアップ](#セットアップ)の `pip install` だけです。
**アノテーションだけなら、それすら要りません**（後述）。

## セットアップ

Python 3.12 で動作確認しています。

```bash
python -m venv .venv
source .venv/bin/activate
pip install faster-whisper          # 文字起こし（CPU / NVIDIA GPU）
pip install mlx-whisper             # 文字起こし（Apple GPU。Mac のとき）
pip install "pyannote.audio>=4.0"   # 話者分離をローカルで回すとき
```

- `annotator.py` は **Python標準ライブラリのみ**で動くため、追加インストールは不要です（上の3つは文字起こしと話者分離のためのものです）。
- **必要なものだけ入れれば動きます。** Mac で完結させるなら `mlx-whisper` と `pyannote.audio` の2つ、GPU 機で D1 を回すなら `faster-whisper` と `whisperx` です。
- Whisperモデルは `./model/` に配置します（CTranslate2形式）。`recordings/` と `model/` は `.gitignore` 済みで、音声・文字起こし・モデルはコミットされません。

### モデルは `large-v3` を推奨します

`./model/` に何を置くかで、精度が大きく変わります。**`large-v3` を推奨します。**

実際のインタビュー音声（日本語・30分・5人）で比較した結果です。左は `large-v3-turbo`
（蒸留版。デコーダが32層→4層）、右は同じ音声を `large-v3` で取り直したものです。

| 発話 | large-v3-turbo | **large-v3** |
| --- | --- | --- |
| 人名 | チラケイト25歳です | **内田圭人**さん |
| 略語 | PTC**J**L / PTC**G**L と割れる | **両方 PTCGL** |
| 一般語 | 紙で読むのと**伝書籍**で | 紙で読むのと**電子書籍**で |
| 専門用語 | 山だったり**虎白のあり手**だったり | 山だったり**トラッシュ**だったり**手**だったり |

固有名詞・専門用語の誤変換は、多くがモデルを上げるだけで消えます。

モデルの取得（CTranslate2形式。`./model/` に置くか、シンボリックリンクを張ります）:

```bash
pip install huggingface_hub
python -c "from huggingface_hub import snapshot_download; \
  snapshot_download('Systran/faster-whisper-large-v3', local_dir='model')"
```

### 動く端末・動かない端末

`large-v3` は **2.9GB**（重みは float16）。`transcribe.py` は `compute_type="float32"` で
読むため、実行時は **6GB前後**のメモリを使います。

| 端末 | 可否 |
| --- | --- |
| NVIDIA GPU（VRAM 8GB以上） | `--device cuda` で快適。30分の音声が1分弱 |
| NVIDIA GPU（VRAM 6GB未満） | float32 では載りません。小さいモデルにするか、`compute_type` の変更が必要 |
| **Apple Silicon (M1〜M4)** | **`--device cuda` は使えません**。CPUのみで動きます（下記） |
| メモリ 8GB未満のマシン | large-v3 は厳しい。`medium` 以下を検討 |

**Apple Silicon では GPU を使えません。** `transcribe.py` が使う CTranslate2 に Metal 対応が
無いためです（実測: `ctranslate2.get_supported_compute_types("cpu")` は
`float32 / int8 / int8_float32` を返し、`"cuda"` は `ValueError`）。
動きはしますがCPU実行なので時間がかかります。Apple GPU を使いたい場合は
mlx-whisper など別系統のツールが必要です。

なお CPU では `int8` にすると所要メモリが約半分になり数倍速くなりますが、
`transcribe.py` は `compute_type` を float32 に固定しているため、
現状は使うにはコードの変更が要ります。

## 1. 文字起こし（`transcribe.py`）

音声（`.wav .mp3 .m4a .flac .ogg`）を入れたディレクトリを指定して実行します。

```bash
python transcribe.py recordings
# GPUを使う場合:
python transcribe.py recordings --device cuda
```

音声ファイルごとに、同じ名前で2種類のテキストが出力されます。

- `<名前>_timecoded.txt` … `[開始s -> 終了s] テキスト` 形式（アノテーターが読み込む）
- `<名前>_text.txt` … テキストのみ

例: `recordings/P7.m4a` → `recordings/P7_timecoded.txt`, `recordings/P7_text.txt`

### Mac で文字起こしする（`transcribe_mlx.py`）

**Apple Silicon なら `transcribe.py` ではなくこちらを使ってください。** MLX で
Apple GPU を使います。M4 での実測（116秒の日本語音声）です。

| 方式 | 速度 | 30分換算 |
| --- | ---: | ---: |
| **`transcribe_mlx.py`（MLX large-v3 / Apple GPU）** | **4.6倍速** | **約6.5分** |
| `transcribe.py` を int8 にした場合（CPU） | 1.2倍速 | 約24分 |
| `transcribe.py` の既定 float32（CPU） | 0.70倍速 | 約43分 |

`transcribe.py` の既定は Mac で**音声より時間がかかります**（0.70倍速）。
CTranslate2 に Metal 対応が無く CPU に落ちるためで、モデルの差ではありません。

```bash
pip install mlx-whisper
python transcribe_mlx.py recordings          # ディレクトリごと
python transcribe_mlx.py 音声.m4a            # 1本だけ
```

`transcribe.py` と同じ `<名前>_timecoded.txt` と `<名前>_text.txt` に加えて、
**`<名前>.words.json`（単語ごとの時刻）**を書きます。これは `diarize_local.py` が
話者を細かく付けるために使うもので、人が読むものではありません。

**量子化版（`-4bit` / `-8bit`）と turbo は使いません。**日本語の固有名詞が
落ちるためです（turbo の実例は上の比較表のとおり）。

既に結果があるファイルは**書き換えません**。作り直すときだけ `--overwrite` を
付けてください。手で直した本文を失わないための歯止めです。

### 外で作った文字起こしを取り込む（`import_whisper.py`）

すでに別の場所で文字起こし済みの場合（GPU機で回した、録音アプリが書き出した、
WhisperX を直接使ったなど）は、取り込むだけで済みます。

```bash
python import_whisper.py <音声とJSON/SRTのあるディレクトリ>
# 音声を実体でコピーする（既定はシンボリックリンク）:
python import_whisper.py <ディレクトリ> --copy
```

指定したディレクトリ配下の JSON（Whisper / WhisperX）と SRT を読み、`recordings/` に
アノテーターが読める `<音声名>_timecoded.txt` と音声を作ります。

**音声とトランスクリプトの組は、ファイル名ではなく「長さ」で突き合わせます。**
録音アプリが書き出すトランスクリプトは音声とファイル名が食い違うことが多く、
名前で対応させると人手で並べ替える羽目になるためです。トランスクリプトの末尾時刻と
音声長がいちばん近いものを組にし、差が大きすぎるもの（既定 60秒。`--tolerance` で変更）は
組にせず警告します。音声長の取得に `ffprobe` を使います。

## 2. アノテーション（`annotator.py`）

```bash
python annotator.py
# → http://127.0.0.1:8000/ をブラウザで開く

# オプション
python annotator.py --port 8001 --dir /path/to/recordings
```

`recordings/` 内の `*_timecoded.txt` を自動で一覧化し、対応する同名の音声を読み込みます。`127.0.0.1` のみにバインドするため、音声がLANに公開されることはありません。

### 画面から文字起こしする

ヘッダーの **「文字起こし」** から、音声の追加・文字起こし・話者分離をまとめて
行えます。CLI を叩かずに済みます。

1. **ファイルを追加** — 取り込み元のディレクトリを開き、音声を選んで実体コピー
2. **処理を選ぶ** — 文字起こし／話者分離のチェックと、モデル・話者の人数
3. **実行** — 進捗が出る。終わるとその収録が開く

**既にある成果物は、確認なしに消しません。** 同名の音声を追加するときは
「上書き / 両方残す」を、文字起こしをやり直すときは消えるファイルの一覧を出して
確認します。手で直した本文と話者ラベルは戻せないためです。

**処理中もアノテーションを続けられます。** 実行を押したらダイアログを閉じて構いません。
処理はサーバー側の別プロセスで走っていて、ヘッダーのボタンが
`文字起こし中… 0:14` に変わって知らせます。押せばいつでも進捗を見られます。

**進捗もサーバーが持っています**。ページを閉じて開き直しても進捗に戻れます。
走らせられるのは一度に1本だけです（GPU を取り合わないため）。

話者分離まで終わると、**そのまま割り当てるかを聞きます**。「あとで」を選んでも、
いつでもヘッダーの「話者を読み込む」から割り当てられます。

#### 使うモデルを増やす

選べるモデルは **`models.json`** に書いてあります。ここに足すと画面の
プルダウンに増えます。**サーバーは実行のたびにこのファイルを読むので、
足したらページを再読み込みするだけでよく、`annotator.py` の再起動は要りません。**

```json
{
  "transcribe": [
    {
      "label": "MLX large-v3（Apple GPU）",
      "model": "mlx-community/whisper-large-v3-mlx",
      "speed": 4.6,
      "note": "既定。固有名詞に強い。30分の音声で約6分半"
    }
  ]
}
```

| 欄 | 意味 |
| --- | --- |
| `label` | 画面に出る名前 |
| `model` | [mlx-community](https://huggingface.co/mlx-community) の HuggingFace リポジトリ名。**初回の実行時に自動で落ちてきます** |
| `speed` | 実測の倍速。所要時間の目安の計算に使うだけで、処理内容は変わりません |
| `note` | プルダウンの下に出る一行説明 |

**既定は `large-v3` です。**プルダウンに1つしか無いのは、これ以外を積極的には
勧めないためで、機能が足りないわけではありません。

- **量子化版（`-4bit` / `-8bit`）と `turbo` は入れていません。** 日本語の
  固有名詞を取りこぼすためです（turbo の実例は上の比較表のとおり）。速さが
  要るときだけ、承知のうえで足してください
- `models.json` に無いモデルは、画面から実行できません。打ち間違えたまま走って
  巨大なモデルが落ちてくるのを防ぐためです

**`models.json` は git 管理しています。** 置換辞書と同じで、チームで同じ
選択肢を共有するためです。

**この画面は、文字起こしのツールが入っていなくても使えます。** `mlx-whisper` や
`pyannote.audio` が無ければ、そのチェックボックスが押せなくなるだけで、
アノテーション自体はこれまでどおり動きます（`annotator.py` 自体は標準ライブラリ
だけで動き、文字起こしは別プロセスに投げているためです）。

### アノテーションだけで使う

**文字起こしのツールを何も入れずに使えます。** 別のところで作った文字起こしを
読み込んで、話者ラベル付けと誤字修正だけに使う、という使い方です。

`annotator.py` が使うのは **Python の標準ライブラリだけ**で、文字起こしと話者分離は
別のプロセスに投げています。入っていなければ、その機能のチェックボックスが
押せなくなるだけで、他はこれまでどおり動きます。

```bash
git clone <このリポジトリ>
cd transcribe_anotator_whisper
python annotator.py          # pip install は要りません
```

`recordings/` に、この2つを同じ名前で置いてください。

```
recordings/P7_timecoded.txt    [12.34s -> 56.78s] テキスト 形式の文字起こし
recordings/P7.m4a              音声
```

`_timecoded.txt` は自分で書いても構いません。1行1発話で、この形式です。

```
[0.00s -> 3.20s] はい、ということでですね
[3.20s -> 5.80s] よろしくお願いします
```

Whisper や WhisperX の JSON・SRT があるなら、[`import_whisper.py`](#外で作った文字起こしを取り込むimport_whisperpy)
が形式を合わせて置いてくれます（こちらも標準ライブラリだけで動きます。
ただし音声とトランスクリプトを長さで突き合わせるので、**`ffprobe` が要ります**）。

起動時に出る行で、いま何が使えるか分かります。

```
この環境でできること: アノテーションのみ（文字起こし・話者分離のツールは未導入）
```

### できること

- **タイムライン連動** — 再生に合わせて該当行がハイライト＆自動スクロール（追従ON/OFF可）。シークバーのクリック／ドラッグ、行の時刻クリックで頭出し。
- **話者の登録** — ヘッダーの「話者を登録」から、人数（2〜9人）と全員の名前をまとめて編集します。ヘッダーに並ぶ話者は表示専用です。4人以上のときは行のボタンが番号だけになり、1行に収まります（番号はそのままキーボードの数字キー）。
- **話者分離の取り込み** — WhisperX や pyannote の結果を読んで自動割り当て（後述）。
- **誤字修正** — 各行のテキストを直接クリックして編集（編集済みは色でマーク）。
- **置換辞書** — 同じ誤変換を「誤 → 正」で一括置換（後述）。
- **セグメント分割 / 結合** — 1行が話者をまたぐとき、カーソル位置で分割。再生位置がその行の範囲内にあればその時刻を境界として使用し、そうでなければ文字位置で按分。上の行と結合も可能。
- **時刻の手動調整** — 各行の開始・終了時刻はダブルクリックで直接編集（`1:02.50` や `62.5` の形式）できるほか、●ボタンで今の再生位置をその時刻にワンクリックで反映できる。分割時のズレや文字起こしの誤差を耳で聞きながら正確に直せる。
- **聞き取れていない発話の追加** — 各行の「＋行」ボタン（または `I` キー）でその行の後に空行を挿入。リスト先頭の「＋ 先頭に行を追加」で一番最初の発話より前にも追加可能。追加した行は時刻を上記の方法で合わせ、テキストを直接入力する（一覧上は「追加」バッジで区別）。
- **行削除 / 元に戻す** — 削除・分割・結合・追加・時刻編集は `⌘Z`（Ctrl+Z）または「元に戻す」で取り消し可能（最大100手前まで）。
- **再生速度** — 0.5〜2×。

### キーボード操作

| キー | 動作 |
| --- | --- |
| `Space` | 再生 / 一時停止 |
| `1`〜`9` | 現在行にロールを付与して次の行へ |
| `0` | ロール解除 |
| `J` / `K`（`↑` / `↓`） | 行を移動 |
| `Enter` | 現在行を編集 |
| `D` | 現在行を削除 |
| `I` | 現在行の後に行を追加 |
| `R` | 現在行を頭から再生 |
| `←` / `→` | 3秒シーク |
| `⌘Z` / `Ctrl+Z` | 削除・分割・結合・追加・時刻編集を取り消し |

### 話者分離の取り込み（自動で割り当てる）

話者分離の結果があれば、**全行の話者を自動で割り当てられます**。
手で1行ずつ付けるより圧倒的に速く、あとは間違いだけ直せば済みます。

収録と**同じ場所に同じ名前で**ファイルを置いてください。

```
recordings/P7_timecoded.txt     ← 文字起こし
recordings/P7.m4a               ← 音声
recordings/P7.json              ← 話者分離（WhisperX の出力）
```

対応する形式は2つです。

| 形式 | 中身 | 出どころ |
| --- | --- | --- |
| `<名前>.json` | テキスト＋話者＋単語時刻 | WhisperX（`--diarize` 付き） |
| `<名前>.rttm` | 話者区間のみ | pyannote、その他の話者分離ツール |

**RTTM** は NIST の Rich Transcription 評価で定められた、この分野の標準形式です。
テキストを持たず「誰がいつ喋ったか」だけを表すので、**別のツールで作った文字起こしに
あとから話者を乗せる**のに使えます。pyannote が `write_rttm()` で直接書けます。

```
SPEAKER <file-id> <ch> <開始秒> <継続秒> <NA> <NA> <話者ID> <NA> <NA>
```

#### 推奨: D1 パイプライン（本文を変えずに話者を足す）

**`diarize_d1.py` を使ってください。** 同じ音声を4通りで作って比べた結果、これが最良でした。

```bash
python diarize_d1.py 音声.m4a --speakers 5
# → 音声.json（話者分離）と、検証用の 音声.b1.txt / 音声.d1.txt
```

3段構えです。

1. **faster-whisper `large-v3`** で文字起こし（VADもバッチも使わない素の設定）
2. その**本文のまま** wav2vec2 で単語の時刻を補正
3. pyannote で話者を分離し、単語へ割り当て

**肝は「2と3で本文を一切変えない」ことです。** 出力された `*.b1.txt`（話者分離前）と
`*.d1.txt`（話者分離後）を diff すれば、自分の音声でも確かめられます。

```bash
diff 音声.b1.txt 音声.d1.txt   # 差が出なければ本文は保たれている
```

#### 4方式の比較（同じ30分のインタビュー・5人・terms なし）

| 方式 | 行数 | 話者 | 割当 | 迷い | 対応なし | 備考 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| large-v3-**turbo**（MLX） | 889 | なし | — | — | — | 固有名詞を取りこぼす |
| **B1** 素の large-v3 | 663 | なし | — | — | — | 本文はこれが基準 |
| **D1**（推奨） | 663 | あり | 658 | 23 | **5** | B1の本文そのまま＋話者 |
| WhisperX フルパイプライン | 160 | あり | 160 | 21 | 0 | 1行が長く、内容の出入りがある |

**D1 を推奨する理由**は3つです。

- **本文が B1 と完全一致** — 精度の良い文字起こしを一文字も損なわずに話者が付く
- **行が文単位（663行）** — 話者を直すのが1行ずつで済む。WhisperX フルは VAD で
  15秒ずつ束ねるので1行が長く、話者をまたぐ行を分割する手間が出る
- **未割当がほぼ無い**（663行中5行）

turbo との差は固有名詞に出ます。

| large-v3-turbo | large-v3 (B1/D1) |
| --- | --- |
| チラケイト25歳です | こちらケイト、25歳です |
| PTC**J**L / PTC**G**L と割れる | 両方 PTCGL |
| 紙で読むのと**伝書籍**で | 紙で読むのと**電子書籍**で |

#### ローカルで話者分離だけ足す（`diarize_local.py`）

**文字起こしが既にあるとき**は、話者分離だけを回せます。`diarize_d1.py` が
whisperx とモデル 5.3GB を要求して実質 CUDA 専用なのに対し、こちらは
**pyannote だけ・モデル 32MB**。Apple Silicon の GPU（MPS）で動きます。

```bash
python diarize_local.py 音声.m4a --speakers 5   # 人数が分かっているとき
python diarize_local.py 音声.m4a                # 自動推定
```

M4 での実測は **12倍速**（30分の音声が約2分半）。`--speakers` で**人数を固定
したほうが精度が出ます**。分からなければ省略すると pyannote が推定します。

出力は隣に置いてある単語の時刻で変わります。

| ある | 出力 | 中身 |
| --- | --- | --- |
| `<名前>.words.json` | `<名前>.json` | 単語ごとに話者。**迷い印が少ない** |
| 無し | `<名前>.rttm` | 話者区間だけ |

**単語の時刻があるほうが良い結果になります。**行の時刻だけで決めると、
Whisper の行の切れ目のずれぶん隣の話者が窓に漏れ込み、票が割れるためです。
同じ30分のインタビューで比べると、**話者の結論は94%一致するのに、迷い印は
23行 → 95行**に増えました。`transcribe_mlx.py` が `.words.json` を出すのは
このためです。`import_whisper.py` で取り込んだだけの収録には単語の時刻が
無いので、RTTM になります（動きますが迷い印は多めに出ます）。

#### D1 とローカルの使い分け

| | `diarize_d1.py` | `transcribe_mlx.py` + `diarize_local.py` |
| --- | --- | --- |
| 動く場所 | NVIDIA GPU（実質） | **Mac の GPU** |
| 文字起こし | faster-whisper large-v3 | MLX large-v3 |
| 単語の時刻 | wav2vec2 で補正 | Whisper 自身の word_timestamps |
| モデル容量 | 約5.3GB | 2.9GB + 32MB |
| 本文 | **B1 と完全一致** | MLX の本文（B1 とは別物） |

**精度を突き詰めるなら D1 のままです。**ローカル版は Mac だけで完結することと
速さのための選択肢で、D1 の置き換えではありません。

#### 必要なもの

`diarize_d1.py` は `whisperx` と HuggingFace のトークンが要ります（pyannote は
ゲート付きモデルのため）。GPU を推奨します。

```bash
pip install whisperx
export HF_TOKEN=hf_xxx        # または ~/.config/whisperx/hf_token に置く
```

CPU でも `--device cpu` で動きますが、実用的な速度は出ません。

**トークンは初回だけです。** pyannote の `speaker-diarization-community-1` は
単一のチェックポイントなので、一度取得すればキャッシュから読めます。
`diarize_d1.py` も `diarize_local.py` も、トークンが見つからなければ自動で
`HF_HUB_OFFLINE=1` に切り替えてキャッシュを読みます。初回はゲートへの同意が
必要なので、[モデルのページ](https://huggingface.co/pyannote/speaker-diarization-community-1)
で同意してからトークンを渡してください。

#### 使い方

**1. 割り当てる** — ヘッダーの **「話者を読み込む」** を押すと、検出された話者
（`SPEAKER_00` など）の一覧が出ます。「割り当てて照合へ」で全行に割り当てます。

**2. 誰がどの話者かを照合する** — 続けて「話者を登録」のパネルが開きます。
`SPEAKER_00` などのラベルに**人の名前を手で付けます**。

```
1  ●  [内田          ]  SPEAKER_00   65行
2  ●  [小平          ]  SPEAKER_01  190行
4  ●  [インタビュアー ]  SPEAKER_03  204行
```

話者分離が付けるのは `SPEAKER_00` のような通し番号だけで、それが誰かは機械には
分かりません。**照合は人がやります。**右の**発話行数**が手がかりになります
（質問する人がいちばん多いことが多い）。

名前を付けたあとも**元のラベルは残る**ので、あとから対応を見直せます。
名前を変えれば、割り当て済みの行も追従します。

割り当ては **⌘Z で丸ごと取り消せます**。

#### 割り当て方（なぜ多数決なのか）

日本語は分かち書きしないため、WhisperX の `words[]` は**1文字ずつ**になります
（30分の音声で9,701件）。文字単位の話者ラベルはバタつくので、そのまま使うと
1つの文の中で話者が何度も入れ替わって使い物になりません。

そこで**行ごとに「重なった時間で重み付けした多数決」**を取り、1人に決めます。
行の時間と話者区間の重なりを話者ごとに合計し、最大の話者を採ります。

**2位と僅差だった行には印**（左端の橙色の線）を付けます。話者分離が迷った場所で、
実際に聞いて直すべき当たりどころです。実データ（30分・5人）では 889行中、
809行に割り当て・36行が迷いあり・80行が対応なし（発話区間の外）でした。

### 置換辞書（同じ誤変換をまとめて直す）

モデルを `large-v3` にしても、同音語・言い間違い・漢字の揺れは残ります。
同じ誤りが何度も出てくるとき、1件ずつ直すのは無駄なので、
**「誤 → 正」の対を辞書に登録して一括置換**します。

登録のしかたは2つあります。

**行を直したついでに登録する（おすすめ）**

行のテキストを直すと、その行に **「辞書へ」** ボタンが出ます。押すと、
直した部分だけが自動で切り出されて辞書に入ります。

```
小平倫太郎です  →  小平凛太郎です     と直して「辞書へ」
   ⇒ 「小平倫太郎 → 小平凛太郎」が登録される
```

1文字だけの違いのときは、**語のかたまりまで自動で広げます**。
「倫 → 凛」で登録してしまうと無関係な「倫理」まで置換してしまうためです。

**辞書を直接ひらいて登録する**

ヘッダーの **「置換辞書」** から一覧を開き、「＋ 行を追加」で足します。
各行の右には、**いま開いている収録の中で何箇所ヒットするか**が出るので、
広すぎる規則（意図せず大量にヒットする）にすぐ気づけます。

**適用**

「この収録に適用」で全行に反映します。結果は「置換 N箇所 / M行」と通知され、
**`⌘Z`（Ctrl+Z）で丸ごと取り消せます**。

置換は次の性質を持ちます。

- **長い語が優先** — 「ポケモンカード」と「ポケモンカードゲーム」の両方があれば長いほうが勝ちます
- **連鎖しない** — 「あ→か」「か→さ」があっても「あ」が「さ」にはなりません（1回だけ置換）
- **正規表現ではない** — `a.c` は `a`, 任意の文字, `c` ではなく、そのままの3文字にマッチします

**辞書はリポジトリ直下の `replacements.json`** に保存されます。`recordings/` は
`.gitignore` されていて共有できないため、意図的にここへ置いています。
チームで育てたい辞書なので、コミットして共有してください。

```json
{
 "replacements": [
  { "from": "こちらケイト", "to": "内田圭人" },
  { "from": "24人", "to": "24歳" }
 ]
}
```

別の辞書を使うには `python annotator.py --replacements path/to/other.json`。

### 書き出し

ヘッダーの「書き出し」で `recordings/<名前>_annotated.txt` を生成します（元の `*_timecoded.txt` は書き換えません）。

- **連続結合** — 同じ話者の連続行を1段落にまとめる。
- **時刻付き** — 各行の先頭に時間を付ける。
- 未ラベルの行は `(未設定)` で出力し、件数を通知します。

### 別の端末に渡して続きをやってもらう

**渡すのは2つだけです。**受け取った側は自分の `recordings/` に置くだけで、
話者も直した本文もそのまま開けます。

```
<名前>.m4a           音声（実体。シンボリックリンクではだめ）
<名前>.annot.json    アノテーションの中身すべて
```

`.annot.json` に、話者の名前・話者分離のラベルとの対応・書き出しの設定・
全行のテキストと話者が入っています。**アノテーターが読むのはこちらが優先**なので、
`_timecoded.txt` が無くても復元できます。

```bash
# 渡す側（-L でリンクの先の実体をコピーする）
cp -L recordings/<名前>.m4a recordings/<名前>.annot.json /渡す場所/

# 受け取る側
cp /受け取った場所/<名前>.* ~/github/transcribe_anotator_whisper/recordings/
python annotator.py
```

**シンボリックリンクに注意してください。** `import_whisper.py` で取り込んだ音声は
リンクなので、そのままコピーすると**リンク切れのファイルが届きます**。`cp -L`、
`tar -h`、`rsync -L` のいずれかを使ってください（画面の「ファイルを追加」で
入れたものは実体なのでそのままで大丈夫です）。

一緒に入れておくと親切なもの:

| ファイル | 受け取った側でできること |
| --- | --- |
| `<名前>_timecoded.txt` | 「再読込」で元の文字起こしに戻せる |
| `<名前>.json` / `.rttm` | 「話者を読み込む」をやり直せる |
| `<名前>.words.json` | 話者分離を回し直せる（人数を変えるときなど） |

`_text.txt` と `_annotated.txt` は書き出した結果なので、渡す必要はありません。

**置換辞書（`replacements.json`）と モデル一覧（`models.json`）はリポジトリ側**です。
収録ごとではなく git で共有します。相手が `git pull` すれば同じものが入ります。

### 収録ごとにできるファイル

`recordings/` には、1つの収録につきいくつかのファイルが並びます。
**名前の部分（`<名前>`）が同じものが1組**です。

| ファイル | 中身 | 作るもの | 消すと |
| --- | --- | --- | --- |
| `<名前>.m4a` など | 音声 | 自分で置く／「ファイルを追加」 | 再生できない |
| `<名前>_timecoded.txt` | 時刻付きの文字起こし。**アノテーターが読む** | 文字起こし | 「再読込」ができない |
| `<名前>_text.txt` | テキストだけ | 文字起こし | 影響なし |
| `<名前>.words.json` | 単語ごとの時刻 | `transcribe_mlx.py` | 話者分離の精度が落ちる |
| `<名前>.json` / `.rttm` | 話者分離の結果 | 話者分離 | 「話者を読み込む」ができない |
| **`<名前>.annot.json`** | **作業の中身すべて**（話者・直した本文・設定） | 編集のたび自動 | **作業が消える** |
| `<名前>_annotated.txt` | 書き出した結果 | 「書き出し」 | 影響なし |

**守るべきは `.annot.json` です。**ここに手でやった作業が全部入っています。
他は作り直せます。

`recordings/` は `.gitignore` 済みなので、音声も文字起こしもコミットされません。
バックアップは別に取ってください。

### 途中復帰

変更のたびに `recordings/<名前>.annot.json` へ自動保存します（アトミック書き込み＋離脱時の送信）。ブラウザやサーバーが落ちても、再起動して同じ収録を開けば続きから再開できます。

トランスクリプトから作り直したいときは、ヘッダーの「再読込」を使います（付与したラベルと編集は失われます）。

## 研究室のサーバーで共有する（`--server`）

GPU 機で1つ立てておき、**LAN にいる人がブラウザから音声を上げて、文字起こし・話者分離・アノテーションまでできる**ようにする形です。
手元で使うとき（`--server` なし）の動き方は変わりません。

```bash
python annotator.py --server --host 0.0.0.0 --port 28630 \
    --data-root ~/transcribe-workspaces \
    --worker-python ~/tool/whisperX/.venv/bin/python   # faster-whisper と pyannote.audio が入った Python
```

| | 手元（既定） | `--server` |
|---|---|---|
| 音声の入れ方 | 取り込み元のフォルダから選ぶ | **ブラウザから上げる**（サーバーの中のフォルダは見せない） |
| 収録の一覧 | `recordings/` を全部 | **人ごとの作業場所**。ほかの人の収録は見えない |
| 文字起こし | `transcribe_mlx.py`（Apple GPU） | `transcribe_cuda.py`（NVIDIA GPU・faster-whisper large-v3） |
| 置換辞書 | リポジトリの `replacements.json` | 作業場所ごと（最初はリポジトリのものの写し） |
| 書き出し | `recordings/` に置く | 置いたうえで、手元に落とす |
| 片付け | しない | **最後に使ってから `--keep-days` 日（既定 7）で作業場所ごと消す** |

- **作業場所**は `--data-root/<推測できない ID>/`。初めて開いたブラウザに作り、cookie で覚えてもらいます。
  文字起こしの画面にその作業場所の URL（`/?ws=<ID>`）が出るので、別の端末からはそれを開けば続きができます。
  **ログインは無く、ID を知っていれば誰でも開けます。**LAN の中だけで使い、URL は人に教えないでください
- **GPU は全員で1本ずつ。**ほかの人の処理が動いていれば順番待ちになり、画面に「前に何件」が出ます。ページを閉じても止まりません。1つの作業場所で同時に走らせられるのは1件だけです
- 消すのは1時間ごとの見回りです。処理中・順番待ちの作業場所は消しません
- アップロードの上限は `--max-upload-mb`（既定 4096）
- 文字起こしのモデルは `models.json` の `transcribe_cuda` に並べたものから選びます。
  初期プロンプトは句読点入りの文で、書き方を誘導しています（`transcribe_cuda.py` の説明を参照）

## 困ったとき

### 「文字起こし」を押しても何も起きない

**サーバーが古いままです。** `webui/` の画面はリクエストのたびに読み直されるので
ボタンは新しく見えますが、`annotator.py` は**起動時に一度読まれたきり**です。
更新したら入れ直してください。

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/api/capabilities
# 200 → 新しい／404 → 古い。入れ直す:
pkill -f annotator.py; sleep 1; python annotator.py
```

そのあとブラウザで **⌘Shift+R**（スーパーリロード）。JS がキャッシュに残っていることがあります。

### 立ち上げ直したのに古いまま

**古いプロセスが生きていて、ポートを掴んだままです。**新しいほうは
`Address already in use` で起動に失敗しています。

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN     # 誰が掴んでいるか
pkill -f annotator.py                 # 落とす
```

### 「文字起こし」「話者分離」のチェックが押せない

そのツールが**サーバーを動かしている Python から見えていません**。仮想環境を
使っているなら、その中の Python で起動してください。

```bash
.venv/bin/python annotator.py     # ← 素の python3 だと .venv の中が見えない
```

起動時のこの行で判断できます。

```
この環境でできること: transcribe_mlx／diarize
```

### 1本目がやたら遅い

**初回だけモデルが落ちてきます**（large-v3 で約2.9GB、pyannote で32MB）。
2本目からは速くなります。

### 話者の人数が合わない

**分かっているなら「話者数」で人数を固定してください。**「自動」は外すことがあります
（実測でも、2人の音声を3人と推定したことがあります）。人数を変えて話者分離だけ
やり直すときは、文字起こしのチェックを外せば数分で済みます。

### 名前を打っている途中でダイアログが閉じる

**直っています**（2026-09-09）。日本語入力の変換を取り消す Escape と、
入力欄から外へのドラッグで閉じていました。まだ起きるなら、上の手順で
サーバーとブラウザを入れ直してください。

### 話者が細かく入れ替わる／`※話者推定に迷いあり` が多い

`<名前>.words.json` が無いまま話者分離した収録です。行の時刻だけで決めると、
行の切れ目のずれで隣の話者が混ざります。`transcribe_mlx.py` で文字起こしし直すと
単語ごとの時刻が付き、迷いが大きく減ります（実測で 95行 → 23行）。

短い相槌の応酬は、これでも残ります。pyannote の時間分解能の限界です。

### 渡したのに相手の端末で音が出ない

**シンボリックリンクをコピーしています。**`cp -L`、`tar -h`、`rsync -L` の
どれかを使ってください。[受け渡しの手順](#別の端末に渡して続きをやってもらう)を参照。

`J` / `K` で行を送りながら `1`〜`9` を押すのが速いです。

## ファイル構成

```
transcribe.py            文字起こしスクリプト（faster-whisper / CPU・CUDA）
transcribe_mlx.py        文字起こしスクリプト（MLX / Apple GPU。Mac ならこちら）
transcribe_cuda.py       文字起こしスクリプト（faster-whisper / NVIDIA GPU。--server が使う）
diarize_local.py         話者分離だけをローカルで行う（pyannote のみ・32MB）
import_whisper.py        外で作った文字起こし（JSON/SRT）を recordings/ に取り込む
diarize_d1.py            推奨の話者分離パイプライン（本文を変えずに話者を足す）
annotator.py             アノテーターのローカルサーバー（標準ライブラリのみ）
webui/                   アノテーターの画面（index.html / app.js / style.css）
replacements.json        置換辞書（誤→正。git管理して共有する）
models.json              画面で選べる文字起こしモデルの一覧（同上）
model/                   Whisperモデル（.gitignore）
recordings/              音声・文字起こし・アノテーション（.gitignore）
workspaces/              --server の作業場所の既定の置き場（.gitignore）
```
